# 13. External Skills Layer

External payloads, dependencies, staging and Telegram. Discovery, review, grants, dependency readiness and enablement are independent: a toggle proves no execution authority. Granted context snapshots reuse §6; protocol: `CREATING_SKILLS.md`.

### Skill gates

`data/skills/` separates native and external data-plane payload buckets; `data/state/skills/<name>/` holds review, grants, enablement, dependencies, tokens and health (§1 Data layout). Discovery confers no trust (§6 Skills and extensions); a conflict declared by either enabled peer is enforced symmetrically without deleting either payload. The executable sequence is install → deterministic preflight → hash-bound multi-model review → grants → dependency readiness → enablement → execution, and the gates stay independent (§10 invariant 8): a review PASS installs no dependencies, `enabled=true` does not prove readiness, and an extension additionally needs host registration. Mutating lifecycle work uses one deduplicated queue (`skill_lifecycle_queue.py`); review jobs keep full private records. Compact UI history shows `running` jobs with dead processes or stale heartbeats as `interrupted` without writing; Skills list reads heal and sync nothing. Review ordinals are allocated after job start under the lifecycle lock: they explain retries, never making a UI counter review authority.

Execution resolves one canonical directory through the full loader per request. Conflict checks use fresh manifest/enablement peers (`skill_peer_inventory.py`), never hashed payloads or partial executable objects. Both scans use `skill_loader._native_platform_visible`: foreign seeds stay hidden except Unix remote on Windows retained by resync (§2). Its provenance survives OFF, preserving later intentional ON, not execution authority. One duck-typed verdict (`skill_conflicts.py`) keeps loaded and peer answers aligned. Both refresh after slow lifecycle work: cross-process disable, revoke or restored-mtime edits apply next request; valid manifests retain conflicts even if payloads are unreadable.

### Skill review authority

These gates govern installed-skill activation. A reviewer's configured rights separately govern checks of untrusted code in its private copy: Full is not an OS sandbox, and checking grants no skill activation.

Skill review combines deterministic preflight with independent multi-model feedback; an optional advisory cannot replace that feedback, and a deterministic preflight failure persists as PENDING, not as advisory-overridable BLOCKERS. Official catalog payloads get their reduced-noise profile only when sidecar, catalog and local file sets and every SHA-256 match a fresh catalog read exactly; the `official_hub_verified` hint in the listing and manifest runs the same match against the display-plane catalog memo (`marketplace/ouroboroshub.py`) and is never authority. Under Advisory an explicit author finish may accept current bytes after prior substantive feedback, or with an exact returned terminal job/hash reference carrying partial feedback or disclosed review unavailability; each finish runs current preflight and records its proof in `author_disposition.review_reference`, and a running critic without feedback is not "unavailable". `SkillReviewState.gate_for` supplies the same current authority to readiness, grants, extension and Host Service consumers; the original critic hash, status and findings never change. Blocking always needs fresh critic approval; Cyber keeps its P0/P3 judgment. Hub publication reuses this authority (§6 Skill publication).

### Telegram seed

The thoughts menu and completion notifier read bounded chat/progress windows from `state/dialog.sqlite` (legacy log paths are addresses only); an unavailable window (importing, a failed segment, an invalid interval) never initializes or advances notification seen IDs, and thoughts keep their preview limits.

`skills/telegram/` owns the in-process bridge and supervised companion (sidecar/tunnel/menu rollback/heartbeat/singleton). Text needs no tunnel. The hash-bound seed needs grants; Colab proves discovery/seed authority, grants missing eligible items under owner auto-grant, then enables. `data/state/skills/telegram/` keeps binding, companion, rollback, cursors, tunnel cache and bounded derived message references; map write faults warn, never stop delivery. Confined files enter `/chat/inject` then `data/uploads`; quiz answers use `/chat/decision`. Other replies carry row/work facts, never routing; status notices reference work, not Main's unseen answer. Earlier same-chat owner messages get native replies. Continue messages stay separate; relay success is silent, failure one line. Oversized files point in-app or to an active Mini App, without starting tunnels or publishing URLs. `lib/telegram_i18n.py` uses `OUROBOROS_UI_LANGUAGE` (§7), preserving host lines; `/language` uses Host `/ui/language`. The completion toggle gates terminal/Main status notices; Off consumes IDs. Replay enriches `completion_notice` (§3), not text. Silent Mode, replies/files/quizzes and salvage stay independent; events only wake one `TypingCue` over `ouroboros/gateway/reply_preparation.py` (DESIGN §9). `TELEGRAM_PROXY` covers Telegram API only, otherwise egress is direct; dependency locked `httpx[socks]`. Limits/proxy forms: `skills/telegram/SKILL.md`.

`list_skills` projects lifecycle state through `skill_catalogue.py`: without a name, sorted pages of whole compact records include disabled, unreviewed, broken and colliding skills, with counted preview omissions. Its snapshot detects membership changes, not payload or state edits; pages are not an atomic state view. `list_skills(name=...)` returns full diagnostics and the exact `manifest.read` call for the loader-selected physical `SKILL.md` or `skill.json`; instructions stay at that source. An unreadable extra payload file does not hide a readable manifest, while an unparsed manifest or colliding name has no manifest address. Unknown names return `found: false`, and oversized details use the generic result source. `model_experience` also reaches the bounded installed-skills context; each `SkillManifestError` carries its repair `fix_hint`.

### Live call seeds

Three native seeds join calls (§6) as peers through the Host Service call door (§12) under the owner's `call_peer` grant. `skills/meeting_audio/` hears the owner's meeting in an owner call: a companion captures the meeting app (ScreenCaptureKit; WASAPI process loopback, else endpoint loopback, disclosed as carrying Ouroboros's whisper; PipeWire links or a Pulse monitor) and on Linux speaks through a null sink and remapped source it loads and unloads. `skills/meeting_browser/` (experimental) is Ouroboros's own Chrome window with a script-replaced microphone; a join reports an unprobed or failed vendor probe; a page refusing that microphone leaves it listen-only. `skills/zoom_meeting/` (Linux) joins Zoom via the Meeting SDK, opens a Presence call when meeting audio flows, takes an OBF token for other accounts' meetings and silences the SDK's credential printout around Join.

### Marketplace installs and dependencies

Marketplace installs are bounded archives staged privately and landed atomically with per-file hash checks; archive validity, extraction paths, checksum and actual loader support remain separate facts, inert resource bytes need no suffix allowlist, and Cyber policy findings are warnings. Install metadata drives isolated dependencies (`marketplace/install_specs.py`); manual instructions remain guidance, not execution. Fresh review and hash-covered declarations authorize literal build/check argv; verified resources and package caches survive under `state/skills/<name>/dependency_cache`, and `deps.json` records resolved package metadata, bytes, outputs and diagnostics. Delivery is distinct from a declared executable check: an absent check stays unknown, and declared-output drift invalidates installed readiness. Updates keep the selected version through retries and show exact version strings without inferring order. `install.PayloadRollbackSnapshot` restores payload, environment and affected lifecycle state for update (adopt: `ouroboroshub._adopt_rollback`); `rolled_back` requires verified restoration and reload, owner enablement and history survive, and a state-write retry keeps already-restored bytes. `marketplace/provenance.py` clears only the local publication record, never a GitHub PR or installed bytes. Script runtimes: `tools/skill_exec.py`, `docs/CREATING_SKILLS.md`.

### Extension import and isolation

Extensions share complete staged trees under `__extension_imports/`, addressed by content hash and runtime/dependency identity, reference-counted per process and reclaimed only when unreferenced with dead owners (`_stage_extension_import_tree`, `extension_import_staging.py`); review/grants stay bound to code. Per-call child processes may proxy tools, routes, WS, UI, settings and companion descriptors, while persistent subscriptions and supervised tasks need in-process or companion lifecycle; the generic capability matrix reports which, never a platform name. Isolated children reuse that staged loader with a scrubbed env. `extension_catalog.json` caches a successful catalog only for a manifest declaring its exhaustive `catalog_inputs` (settings and environment keys; the key hashes runtime, host revision, grants and the declared values, never persisting them); registration that depends on anything else keeps its catalog child, and no bundled payload is implicitly opted in (`extension_import_staging.declared_catalog_inputs`). In-process extensions are the powerful path, so namespacing, declared permissions, per-skill tracking and atomic unload are an executable contract, not convention. Skill repair enqueues an ordinary managed task admitted against one exact payload revision (`skill_repair_admission.py`; §6 Skills and extensions); a `skill_repair` constraint, still produced by the bucket + skill-name short form and canonicalized to `normal` at promotion, selects the payload only and grants no reduced tool profile. An installed payload needs no Git copy, and review never forces unload merely because the caller is repairing it.

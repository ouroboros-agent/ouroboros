# 13. External Skills Layer

Built-in and installed payloads, dependencies, staging and Telegram. Discovery, review, grants, dependency readiness and enablement stay separate facts because collapsing any two turns a UI toggle into execution authority. Granted context snapshots reuse §6; protocol: `CREATING_SKILLS.md`.

### Skill gates

Discovery confers no trust; a review PASS installs no dependencies; `enabled=true` does not prove readiness. Payloads live under `data/skills/`; lifecycle state under `data/state/skills/<name>/` (§1). The sequence is install → deterministic preflight → digest-bound review or acceptance → grants → dependency readiness → enablement → execution; extensions also need host registration (§10 invariant 8). Either enabled peer's declared conflict applies symmetrically without deletion. One deduplicated queue (`skill_lifecycle_queue.py`) owns mutations. Panels lend the lane and persist only for still-installed bytes. Review jobs keep full private records; UI history projects dead-process/stale-heartbeat jobs as interrupted without writing. Skills list reads heal nothing. Ordinals are allocated under the lifecycle lock after job start, so retry history stays explainable without a UI counter becoming review authority.

Execution resolves one canonical directory through the full loader per request. Conflict checks use fresh manifest/enablement peers (`skill_peer_inventory.py`), never hashed payloads or partial executable objects. Both scans use `skill_loader._native_platform_visible`: foreign built-ins stay hidden except Unix remote on Windows retained by re-seed (§2). Its provenance survives OFF, preserving later intentional ON, not execution authority. One duck-typed verdict (`skill_conflicts.py`) keeps loaded and peer answers aligned. Both refresh after slow lifecycle work: cross-process disable, revoke or restored-mtime edits apply next request; valid manifests retain conflicts even if payloads are unreadable.

### Skill review authority

These gates govern installed-skill activation. A reviewer's configured rights separately govern checks of untrusted code in its private copy: Full is not an OS sandbox, and checking grants no skill activation.

Preflight failure persists as PENDING, never advisory-overridable BLOCKERS. Records bind the release digest (`skill_identity.py`: payload plus dependency declarations, without install notes); conversion rebinds only proven unchanged bytes. Host facts admit exact bytes without a panel: trusted source, `self_check` (Cyber Pro only), owner Skip, or owner edit by the owner's selected-skill task. In ordinary tasks, owner-requested edits use `skill_owner_action` Skip with `owner_source` carrying the owner's words. Edits invalidate earlier acceptance. Review-source blockers stay off under Advisory, author finish included. Elsewhere Advisory author finish accepts after substantive feedback or an exact terminal job/hash reference carrying partial feedback or disclosed unavailability; it runs preflight and records `author_disposition.review_reference`. A running critic without feedback is not unavailable. `SkillReviewState.gate_for` supplies one authority without rewriting critic facts; Blocking needs fresh approval, Cyber keeps P0/P3 judgment. Publication: §6.

### Telegram built-in

The thoughts menu and completion notifier read bounded chat/progress windows from `state/dialog.sqlite` (legacy log paths are addresses only); an unavailable window (importing, a failed segment, an invalid interval) never initializes or advances notification seen IDs, and thoughts keep their preview limits.

`skills/telegram/` owns the in-process bridge and supervised companion (sidecar/tunnel/menu rollback/heartbeat/singleton). Text needs no tunnel. The built-in (`skill_builtin.py`) needs grants; Colab waits for its executable install, grants missing eligible items under owner auto-grant, then enables. `data/state/skills/telegram/` keeps binding, companion, rollback, cursors, tunnel cache and bounded derived message references; map write faults warn, never stop delivery. Confined files enter `/chat/inject` then `data/uploads`; quiz answers use `/chat/decision`. Other replies carry row/work facts, never routing; status notices reference work, not Main's unseen answer. Earlier same-chat owner messages get native replies. Continue messages stay separate; relay success is silent, failure one line. Oversized files point in-app or to an active Mini App, without starting tunnels or publishing URLs. `lib/telegram_i18n.py` uses `OUROBOROS_UI_LANGUAGE` (§7), preserving host lines; `/language` uses Host `/ui/language`. The completion toggle gates terminal/Main status notices; Off consumes IDs. Replay enriches `completion_notice` (§3), not text. Silent Mode, replies/files/quizzes and salvage stay independent; events only wake one `TypingCue` over `ouroboros/gateway/reply_preparation.py` (DESIGN §9). `TELEGRAM_PROXY` covers Telegram API only, otherwise egress is direct; dependency locked `httpx[socks]`. Limits/proxy forms: `skills/telegram/SKILL.md`.

`skill_catalogue.py`: `list_skills` pages whole compact records, including disabled, unreviewed, broken and colliding skills, with counted omissions. Snapshots track membership only; pages are not atomic. Named reads give full diagnostics and `manifest.read` for the loader-selected `SKILL.md` or `skill.json`; bodies stay there. Unreadable payloads do not hide readable manifests; unparsed/colliding manifests have no address. Unknown names return `found: false`; oversized details use the generic result source. `model_experience` reaches bounded context; `SkillManifestError` carries `fix_hint`. Delegate index: §6.

### Live call seeds

Three native seeds join calls (§6) as peers through the Host Service call door (§12) under the owner's `call_peer` grant. `skills/meeting_audio/` hears the owner's meeting in an owner call: a companion captures the meeting app (ScreenCaptureKit; WASAPI process loopback, else endpoint loopback, disclosed as carrying Ouroboros's whisper; PipeWire links or a Pulse monitor) and on Linux speaks through a null sink and remapped source it loads and unloads. `skills/meeting_browser/` (experimental) is Ouroboros's own Chrome window with a script-replaced microphone; a join reports an unprobed or failed vendor probe; a page refusing that microphone leaves it listen-only. `skills/zoom_meeting/` (Linux) joins Zoom via the Meeting SDK, opens a Presence call when meeting audio flows, takes an OBF token for other accounts' meetings and silences the SDK's credential printout around Join.

### Sources, installs and dependencies

`skill_sources.py` owns the source list. Defaults until chosen: Official trusted, Community review; trust changes affect future installs. Git caches in `state/skill_sources/` read github.com HTTPS without the configured GitHub token, then retry authentication refusals once with it alone. Other URLs use host credentials. Hubs provide entries, digest endorsements and categories; plain repos, manifest folders. `skill_source_install.py` verifies releases and records basis. Ouroboros uses `check: review` (panel); only in Cyber Pro may it pick `self` (reads the exact release, records why); trusted sources skip it. HTTP: `ouroboros/gateway/skill_source_contracts.py`.

Updates compare candidate and optional local digests. Replace keeps `.previous`; keep skips; merge uses the owner's task door. Review-basis updates retain payload and lifecycle state; `pending_update` names the candidate. Completion, owner Skip and background startup settle in the lane: accept executable bytes or restore and reconcile, recording `update_rejected` for review, preflight or landing/dependency failure. Startup leaves live reviews alone. The pre-update record restores an interrupted landing; superseded installs discard snapshots. Partial restores keep evidence and never replace payload twice. Update without review binds `owner_skip` to the exact release. Starters accept any source; absent/blank selects defaults, `[]` none. `OUROBOROS_STARTER_SKILLS_TURN_ON` defaults true (§7); built-ins precede git fetches.

ClawHub archives land atomically with per-file hashes. Accepted dependency declarations authorize literal build/check argv (`marketplace/install_specs.py`); manual instructions stay guidance. Caches live in `state/skills/<name>/dependency_cache`, results in `deps.json`; absent checks stay unknown and drift invalidates readiness. `provenance.py` clears only the local receipt. Script runtimes: `tools/skill_exec.py`, `docs/CREATING_SKILLS.md`.

### Extension import and isolation

Extensions share complete staged trees under `__extension_imports/`, addressed by content hash and runtime/dependency identity, reference-counted per process and reclaimed only when unreferenced with dead owners (`_stage_extension_import_tree`, `extension_import_staging.py`); review/grants stay bound to code. Per-call child processes may proxy tools, routes, WS, UI, settings and companion descriptors, while persistent subscriptions and supervised tasks need in-process or companion lifecycle; the generic capability matrix reports which, never a platform name. Isolated children reuse that staged loader with a scrubbed env. `extension_catalog.json` caches a successful catalog only for a manifest declaring its exhaustive `catalog_inputs` (settings and environment keys; the key hashes runtime, host revision, grants and the declared values, never persisting them); registration that depends on anything else keeps its catalog child, and no bundled payload is implicitly opted in (`extension_import_staging.declared_catalog_inputs`). In-process extensions are the powerful path, so namespacing, declared permissions, per-skill tracking and atomic unload are an executable contract, not convention. Skill repair enqueues an ordinary managed task admitted against one exact payload revision (`skill_repair_admission.py`; §6 Skills and extensions); a `skill_repair` constraint, still produced by the bucket + skill-name short form and canonicalized to `normal` at promotion, selects the payload only and grants no reduced tool profile. An installed payload needs no Git copy, and review never forces unload merely because the caller is repairing it.

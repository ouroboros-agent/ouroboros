# Gateway Boundary Pattern

This chapter owns dependency direction at the browser boundary: inbound routes enter through `ouroboros/gateway/`, outbound provider and harness adapters live in `ouroboros/gateways/` and carry no domain policy, and every interface, the builtin one included, is a client of one published contract (why the facade exists: ARCHITECTURE §1 "Gateway Boundary v1").

Frontend calls go through `web/modules/api_client.js`. Do not promote the `gateway/host_service.py` callback surface into a general owner/task API, and do not require a class where established function owners already preserve the boundary. Enforcement: CHECKLISTS item 23 (`gateway_parity`) and `tests/test_gateway_parity.py`.

Publish each browser route or WS type via its `ouroboros/gateway/endpoint_index.py` token and `HTTP_SHAPES`/`WS_SHAPES` binding to contract TypedDicts with field-identical JSDoc twins; `GET /api/contract` derives from these. Every `/api` or `/auth` address the builtin SPA builds is typed, so replacement clients rely on the same contract. Update client-visible meaning in `docs/CLIENT_CONTRACT.md` with the code. The wizard and author kit never load from the selected interface. Enforcement: `tests/test_client_contract_coverage.py`, `tests/test_gateway_client_contract.py`, `tests/test_client_contract_bindings.py`, `tests/test_ui_serving.py`.

Named skill chat ingress writes through the message-bus canonical writer before enqueue and correlates reads and cancel by `operation_ref` (custody, replay and the 409 rules: ARCHITECTURE §12). A cancel or intent write addresses the same installation root as the operation being read, and operation reads and cancel verify the complete source against actual task or direct-turn ownership; presentation annotations are discovery hints only. Tests: `tests/test_host_service_operation_identity.py`, `tests/test_host_service_operations.py`.
